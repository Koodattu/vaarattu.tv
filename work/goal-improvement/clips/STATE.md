## Scope and decisions

- Users browse a moment, search by title/game/clipper, sort most viewed/newest, filter recent or Twitch-featured clips, watch/share a permalink, and return with filters/page intact. Defaults: most viewed, all time. The home section shows popular clips with truthful counts, not a fabricated editorial selection.
- Reuse the VOD visual language, native forms, Pagination, cancellable request hook and hostname hook. The established dark/slate/Geist/purple interface is the visual direction; end-user-ui-ux, Impeccable craft floor and TDD guide states and verification. No modal, animation, new package or parallel design system.
- Collector stores metadata only, never video files. Existing streamer authentication suffices; no scopes or auth policy change. Import starts independently of stream/chat collection and cannot block them. Full catalog scans use split date windows to avoid Twitch's approximate1000-result cap, with an explicit request budget. Failed/incomplete scans retain saved data. Missing clips are checked by ID before marking unavailable; no record deletion.
- Clip fields are a snapshot of external metadata, including game/creator display names. A single additive table avoids creating local viewers solely for clip authors. IDs/URLs are validated and external errors never log credentials. Exact VOD IDs may link a clip to a recorded stream; no timestamp/title guessing.
- Twitch's clip iframe has a documented400x300 minimum and no interactive SDK. On narrower containers, offer direct Twitch playback; on desktop load one player after user intent, keep a provider fallback visible, and do not claim an iframe load proves video availability.
